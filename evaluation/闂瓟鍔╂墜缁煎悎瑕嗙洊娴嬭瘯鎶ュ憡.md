# 面向航空工程材料损伤分析的多智能体个性化知识生成与实操训练系统

> 正式部署请优先阅读 [DEPLOYMENT_GUIDE.md](D:/agents/DEPLOYMENT_GUIDE.md)；比赛材料与软件模块逐项映射见 [COMPETITION_DELIVERY_GUIDE.md](D:/agents/COMPETITION_DELIVERY_GUIDE.md)。脱敏候选包由 `scripts/build_release_package.ps1` 自动生成。

## 项目背景

本项目面向“领域知识个性化生成与多智能体协同决策系统研究”比赛，聚焦航空工程材料损伤分析技能培训。系统围绕航空轮胎胎面橡胶、航空刹车片和飞机复合材料板的典型损伤识别、机理分析、实验表征和维护判读训练，构建“学情画像构建 -> 多智能体协同调度 -> 领域知识个性化生成 -> 专家审核纠偏 -> 交互反馈 -> 动态决策更新”的完整闭环。

当前版本已经升级为真实工程增强版：前端 React + Vite，后端 FastAPI，MySQL 持久化学习过程数据，Elasticsearch 检索航空工程材料知识库，mock LLM 稳定兜底，本地 JSON 作为 seed 与 fallback。

第七阶段进一步补强了知识库构建证据链、RAG 检索扩展、50 条测评用例、幻觉防控和数据合规材料。系统现在不只是内置 JSON 知识库，还提供 `knowledge_corpus/` 语料目录、MinerU/Markdown 解析接入方式、切片清单和 RAG 管线。

## 技术栈

- 前端：React + Vite
- 后端：FastAPI
- 数据持久化：MySQL + SQLAlchemy
- 知识库检索：Elasticsearch
- 基础数据：本地 JSON
- 生成模式：mock/template 默认启用
- LLM 能力：OpenAI-compatible API、结构化输出校验、RAG 约束动态追问和失败自动回退
- 测试：pytest

## 第七阶段补强内容

- 知识库证据链：新增 `knowledge_corpus/raw_docs/`、`parsed_docs/`、`chunks/` 和 `index_manifest.json`。
- MinerU 接入方式：当前支持读取 MinerU 输出的 Markdown，不强制做前端 PDF 上传。
- RAG 管线：新增 `backend/app/rag/chunker.py`、`embedder.py`、`pipeline.py`。
- 检索模式：支持 `bm25`、`vector`、`hybrid` 三种模式；默认 hybrid，在无 BGE 时自动退化为 BM25。
- BGE 扩展：通过 `BGE_ENABLED`、`BGE_MODEL_PATH`、`EMBEDDING_BACKEND` 控制，默认关闭。
- 测评集：新增 `evaluation/eval_cases.json`，包含 50 条测试用例。
- 质量文档：新增幻觉防控、知识溯源、RAG 检索、测试评价和数据合规说明。
- 多维测评：在 50 条核心用例外新增 10 条事故、维修、实验和检测方法增强用例。
- 团队实验模板：新增航空轮胎热氧老化/滑动磨损记录、损伤图像标注、脱敏规范和入库前校验器。

## 系统功能

1. 学习者画像输入与演示案例一键加载。
2. 航空轮胎、航空刹车片、复合材料板三类训练方向。
3. 按训练方向读取诊断题并计算学情结果。
4. 六 Agent 协同闭环展示。
5. Elasticsearch 优先检索领域知识库，失败自动回退 JSON。
6. 生成讲义、实操指南、分阶测试题和案例任务。
7. 专家审核纠偏与知识依据展示。
8. 学情报告展示与 Markdown 导出。
9. 反馈测试后动态更新学习路径。
10. MySQL 持久化诊断、Agent 会话、资源、报告和反馈记录。
11. 多智能体智能训练工作台：用户可围绕当前训练会话自由提问；界面同步展示学习上下文、多轮对话、Agent 轨迹、RAG 证据、审核闸门和路径决策。
12. 动态回答绑定 evidence_ids、知识来源、适用边界和下一步训练任务；SQL 模式下写入 `learning_interactions`。
13. 长任务实时进度：FastAPI 通过 SSE 推送 Agent 开始、完成、纠偏重生和持久化事件；前端同时显示已用时间和预计剩余时间，SSE 断开时自动切换任务轮询。
14. 任务恢复能力：支持合作式停止、失败或取消后重试，模型异常仍沿用既有 mock/template 自动回退。
15. 历史训练会话：从 MySQL 恢复画像、诊断、Agent 步骤、个性化资源、动态问答和学情报告。
16. 页面刷新续跑：浏览器仅暂存任务 ID 和任务类型，刷新后自动连接原任务，不会重复发起模型请求；恢复指针 30 分钟自动失效。
17. 执行可观测性：任务响应记录管线总耗时和逐 Agent 耗时，协同页显示真实执行摘要；历史会话支持关键词和训练方向筛选。
18. 全局上下文智能助手：首页和全部训练页面均可唤起；前端自动传递当前页面、训练方向、画像、诊断结果、会话 ID 与可见内容摘要。
19. 分层响应策略：系统操作问题由界面理解与导航决策 Agent 即时回答；当前得分、薄弱点、强项和目标由页面上下文快速解释；专业问题执行材料路由、RAG 检索、个性化讲解、审核纠偏和路径决策。
20. 助手交互韧性：支持停止任务、失败重试、清空记录和 24 小时本地问答续接；回答卡直接显示 LLM/Mock、ES/JSON、证据 ID、证据标题与适用边界。

## 多智能体架构

系统至少包含 6 个职责明确的 Agent：

- 学情诊断 Agent：分析答题结果、基础水平和知识薄弱点。
- 材料领域路由 Agent：选择航空轮胎、航空刹车片或复合材料方向。
- 专业知识检索 Agent：从 Elasticsearch 或 JSON fallback 检索知识依据。
- 个性化资源生成 Agent：生成讲义、实操指南、分阶测试题和案例任务。
- 专家审核纠偏 Agent：检查专业错误、依据不一致、难度不匹配和幻觉风险。
- 学习路径决策 Agent：规划学习路径、难度匹配和下一步训练建议。

## 三种运行方式

### 1. 纯 mock / JSON 演示模式

不依赖 MySQL，不依赖 Elasticsearch，适合作为兜底演示。

```env
DATABASE_ENABLED=false
DATA_BACKEND=json
ES_ENABLED=false
LLM_ENABLED=false
```

特点：

- 无需 Docker 服务。
- 本地 JSON 提供画像、题库和知识库。
- 可完整演示“加载演示案例 -> 提交诊断 -> Agent 流程 -> 资源生成 -> 学情报告 -> 导出报告 -> 反馈迭代”。

### 2. SQL + ES 工程模式

推荐正式答辩和录屏使用。

```env
DATABASE_ENABLED=true
DATA_BACKEND=sql
ES_ENABLED=true
LLM_ENABLED=false
```

特点：

- MySQL 保存学习过程数据。
- Elasticsearch 检索航空工程材料知识库。
- 前端首页和 `/api/health` 可展示真实工程状态。
- mock LLM 保证生成结果稳定。

### 3. 真实 LLM 增强模式

预留真实模型调用，但当前正式演示不建议启用。

```env
LLM_ENABLED=true
LLM_BASE_URL=https://your-api.example.com/v1
LLM_API_KEY=your_key
LLM_MODEL=your_model
LLM_TIMEOUT=60
LLM_MAX_TOKENS=1800
LLM_RETRIES=1
```

`LLM_BASE_URL` 应填写 OpenAI-compatible API 的版本根路径，例如以 `/v1` 结尾，客户端会调用 `/chat/completions`。启用后，资源生成和启发式追问优先使用真实模型；输出必须通过 JSON 结构、证据 ID 和专业边界检查。调用失败或输出不合格时，系统自动回退 mock/template，不中断原演示流程。API Key 仅写入本机 `backend/.env`，不要提交仓库。

2026-08-11 已使用阿里云百炼 Qwen `qwen-plus` 完成端到端验证：资源生成 `generation_mode=llm`，动态追问 `generation_mode=llm`，审核为 `llm-assisted-review`，结果写入 MySQL。Qwen 结构化调用使用 `response_format={"type":"json_object"}`，并按官方建议不设置 `max_tokens`，防止长 JSON 被截断。单次验证中资源生成约 37.8 秒、动态追问约 10.7 秒，延迟会随网络和模型负载变化。

2026-08-12 进一步完成 6 个代表性真实 Qwen 场景回归：覆盖本科生降维解释、`60 N / 160 m` 精确工况、连续追问、剩余寿命拒答、维修放行拒答和复合材料无损检测，机器检查 6/6 通过。真实 LLM 与 Elasticsearch 使用率、证据闭合、输入理解、专业安全、画像适配和 Agent 执行得分均为 100%；3 条候选回答被审核 Agent 驳回后由证据模板重生。该结果属于工程机器测评，正式专业结论仍需领域专家抽样复核。

### 对话式智能训练闭环

完成诊断和六 Agent 主流程后，进入“智能训练工作台”输入未预置的领域问题。每轮对话执行：

```text
材料路由 -> RAG 检索 -> 个性化讲解 -> 审核纠偏 -> 路径决策
```

工作台不是通用聊天框：它持续携带学习者画像、诊断薄弱点、训练方向和学习目标。接口返回回答、讲解层级、证据 ID 与标题、检索模式、知识来源、适用边界、启发式追问、实操任务、下一动作和 5 个 Agent 步骤；右侧审核闸门还显示候选回答是否被驳回、纠偏稿是否采用及有效引用数量。每次交互记录提示词版本、模型、调用耗时、结果与回退原因；历史对话可从 MySQL 恢复，并自动进入学情报告和 Markdown 导出。`LLM_ENABLED=false` 时接口仍可运行，但页面会明确标注“模板兜底生成”；只有实际配置并调用成功时才标注“真实 LLM 生成”。

### 全局上下文智能助手

首页“打开智能助手”和右下角“问问助手”可在诊断前及训练全过程使用。助手接收结构化页面上下文，不截取桌面或读取屏幕外信息。操作导航采用快速规则路径；当前得分、薄弱点、强项、目标和训练方向采用已确认页面状态快速回答；材料机理与实验工况采用 5 Agent 证据约束路径。已有 `session_id` 时专业回答绑定当前会话并进入学习记录；无会话时使用临时画像与方向上下文，不写入正式训练会话。前端支持停止、重试、清空及 24 小时最近问答续接，并展示生成模式、知识来源、证据标题和回答边界。接口为 `POST /api/assistant/ask` 和异步入口 `POST /api/assistant/tasks`。

## RAG 与知识库构建

知识库构建材料位于：

```text
knowledge_corpus/
├─ raw_docs/
├─ parsed_docs/
├─ chunks/
├─ source_registry.json
├─ MATERIAL_COLLECTION_GUIDE.md
├─ index_manifest.json
└─ README.md
```

资料查找、版权判断、文件命名、MinerU 清洗和证据定位规则见 `knowledge_corpus/MATERIAL_COLLECTION_GUIDE.md`。新增资料必须先登记 `source_registry.json`，再进入解析和切片流程。

从 Markdown 切片并可选入 ES：

```powershell
cd D:\agents\backend
.\.venv\Scripts\Activate.ps1
python -m app.rag.pdf_parser
python -m app.rag.structured_parser
python -m app.rag.pipeline
```

注意：正式演示前不需要重复运行该 pipeline。当前 ES 演示索引固定为 1,766 条；只有新增资料、调整解析页范围或重新切片时才需要执行。结构化解析器用于开放获取论文 JATS XML 和 Zenodo 元数据，PDF 仍由 `pdf_parser` 或 MinerU 处理。

默认无 BGE 依赖。如果要启用本地 BGE，请提供模型目录并设置：

```env
BGE_ENABLED=true
BGE_MODEL_PATH=D:\models\bge-small-zh-v1.5
EMBEDDING_BACKEND=bge
RETRIEVAL_MODE=hybrid
```

正式比赛演示建议仍保持 `BGE_ENABLED=false`，将 BGE 作为技术扩展亮点。
