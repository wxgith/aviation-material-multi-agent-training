# 最终人工审核指南

本指南用于项目负责人在正式提交前，对系统、界面、PPT、报告、测试证据和比赛提交包进行一次人工终验。建议按顺序执行并逐项打勾，不要边审核边继续开发新功能。

## 一、先确认参赛资格与时间

- [ ] 参赛成员均符合学生赛道身份要求；团队不超过 10 人，指导教师不超过 3 人。
- [ ] 已在挑战杯系统完成报名，并已有审核通过的报名表。官方报名时间为 2026-05-30 至 2026-06-30；当前如尚未报名，应立即联系学校组织方或发榜单位确认补救方式。
- [ ] 记住作品提交截止时间：2026-09-05 前。
- [ ] 记住提交邮箱：`602808600@qq.com`。
- [ ] 报名表中的学校、申报人、团队成员、作品名称与最终材料完全一致。

## 二、自动化运行审核

### 1. Docker 与工程状态

先启动 Docker Desktop，确认 MySQL 与 Elasticsearch 容器正在运行：

```powershell
docker ps --format "table {{.Names}}\t{{.Image}}\t{{.Status}}\t{{.Ports}}"
```

预期至少看到：

- `report-mysql`，端口 `3306`；
- `agents-es`，端口 `9201`。

### 2. 一键启动与状态确认

```powershell
cd D:\agents
.\scripts\start_project.ps1
.\scripts\project_status.ps1
```

状态脚本显示 `Project status: READY` 后，可直接进入前端。以下手工启动后端、前端命令保留用于故障定位。

### 2.1 手工启动后端

```powershell
cd D:\agents\backend
.\.venv\Scripts\Activate.ps1
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

访问 `http://127.0.0.1:8000/api/health`，检查：

- [ ] `backend_status=ok`；
- [ ] `data_backend=sql`；
- [ ] `database_connected=true`；
- [ ] `es_connected=true`；
- [ ] `knowledge_source=elasticsearch`；
- [ ] `llm_enabled=false`；
- [ ] ES 索引切片数口径为 1,766。

### 3. 手工启动前端

新开 PowerShell：

```powershell
cd D:\agents\frontend
npm run dev
```

访问 `http://127.0.0.1:5173`。

### 4. 最终自动验收

另开 PowerShell：

```powershell
cd D:\agents
.\scripts\run_acceptance.ps1
```

预期：

- [ ] 后端 `116 passed`；
- [ ] 前端生产构建通过；
- [ ] ES 1,766 条；
- [ ] 核心用例 50/50；
- [ ] 六 Agent 完整率 100%；
- [ ] JSON/mock fallback 通过；
- [ ] 专家确认状态为 `electronic_confirmation_recorded`。

验收报告：`outputs/acceptance/acceptance_latest.md`。

若完整验收停在第 3 步，先不要重跑全部流程。单独执行：

```powershell
cd D:\agents
.\scripts\run_acceptance.ps1 -OnlyStep 3
```

确认终端中每个 `START` 都有对应 `DONE`，并检查 `outputs/acceptance/logs/` 下最新的 `core-evaluation` 日志。具体操作见 `docs/验收卡顿排查说明.md`。

## 三、界面与完整流程审核

浏览器建议使用 1920x1080、缩放 100%。从首页开始，按以下顺序操作：

1. 点击“加载演示案例”。
2. 检查画像是否为本科低年级学生、方向是否为航空轮胎、目标是否为热氧老化与滑动磨损。
3. 提交诊断，检查得分、强项、薄弱点和诊断总结是否出现。
4. 进入多智能体协同页，确认 6 个 Agent 均为完成状态。
5. 展开 RetrievalAgent，确认显示 Elasticsearch、检索模式、证据标题、evidence_id 和分数。
6. 检查四类资源：讲义、实操指南、分阶测试题、案例任务。
7. 检查 ReviewAgent 是否展示风险点、证据一致性、使用边界和纠偏结论。
8. 进入学情报告，检查知识盲区、难度轨迹、学习路径和下一步建议。
9. 点击“导出学情报告”，打开下载的 Markdown，确认中文正常、字段完整。
10. 提交反馈测试，分别验证低分与高分时的降维解释、巩固、补充案例或进阶挑战。
11. 返回首页点击“工程检索案例”，确认 60 N、160 m、趋势图、实验形貌、证据 ID 和限制说明完整显示。

界面重点检查：

- [ ] 所有按钮可点击，点击后页面与导航状态一致；
- [ ] 没有空白卡片、重叠、横向溢出或中文乱码；
- [ ] 页面刷新后不会出现无法继续的异常状态；
- [ ] SQL/ES 状态、50/50、电子确认信息显示正确；
- [ ] 不展示数据库密码、真实个人隐私或 API Key。
