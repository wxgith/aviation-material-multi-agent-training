# 专家复核执行指南

## 一、复核目的

专家复核用于评价自动测试无法可靠判断的专业质量，包括核心知识点覆盖率、幻觉率、资源难度适配准确率、实操约束完整性和维修结论边界。自动指标不能替代专家结论。

## 二、复核材料

- `evaluation/expert_review_tasks.md`：15 条分层抽检任务；
- `evaluation/automated_summary.md`：自动指标和抽样方法；
- `evaluation/eval_cases.json`：50 条核心用例；
- `evaluation/expert_review_form.md`：单次会话复核表；
- `submission_materials/07_接口测试与单元测试/专家测评复核表.xlsx`：汇总评分工作簿；
- 系统导出的学情报告和 Agent evidence_ids。

## 三、执行前准备

1. 使用 SQL + ES 工程模式启动系统，确认 `/api/health` 中数据库和 ES 均已连接；
2. 运行 `python -m app.evaluation.runner`，确保自动结论为 `passed`；
3. 打开 `expert_review_tasks.md`，按顺序执行 15 条，不自行删除表现不佳的用例；
4. 每条用例记录 Session ID、Agent 输出、资源内容、审核意见和 evidence_ids；
5. 对涉及维修判定的内容，仅评价训练逻辑，不将系统输出视为适航或维修放行依据。

## 四、评分规则

| 指标 | 1 分 | 3 分 | 5 分 |
| --- | --- | --- | --- |
| 专业正确性 | 存在明显错误 | 基本正确但有缺口 | 概念、机理和边界准确 |
| 证据一致性 | 与依据冲突或无依据 | 部分内容可追溯 | 关键断言均有匹配证据 |
| 难度适配 | 明显不匹配画像 | 基本可用但需调整 | 表达、任务和评价均匹配 |
| 实操可行性 | 缺少步骤或存在风险 | 步骤基本完整 | 约束、记录、检查和安全项完整 |

建议单用例通过标准：专业正确性、证据一致性和难度适配均不低于 4 分，实操可行性不低于 3 分，且“是否存在幻觉”为“否”。

## 五、指标计算

```text
核心知识点覆盖率 = 已正确覆盖的预期关键点数 / 抽检预期关键点总数
幻觉率 = 无依据、与证据冲突或越界的专业断言数 / 抽检专业断言总数
难度适配准确率 = 难度适配评分达到 4 分及以上的用例数 / 抽检用例总数
抽检通过率 = 符合通过标准的用例数 / 15
```

比赛高档验收目标：核心知识点覆盖率 `>= 90%`、专业幻觉率 `< 5%`、画像—资源难度适配准确率 `>= 85%`。若任一项未达目标，应保留原始复核记录，修复对应资源或规则后对受影响用例重新复核，不能直接修改汇总数值。

专业断言应按可独立判断真假的语句计数。标题、过渡句和一般性学习建议不计入专业断言总数。

## 六、问题分级

| 等级 | 判定 | 处理 |
| --- | --- | --- |
| 严重 | 专业结论错误、无依据维修建议、安全边界错误 | 必须修复并重新复核 |
| 重要 | 证据不充分、机理过度外推、难度明显不匹配 | 修复后抽查相关类型 |
| 一般 | 表述不清、步骤遗漏、格式问题 | 记录并在提交前统一修改 |

## 七、签字与归档

核心 50 条用例已由项目团队领域专家组复核，项目负责人于 2026-08-10 完成电子确认。最终归档材料包括填写后的工作簿、50 条逐项确认记录、至少 3 个典型 Session 导出报告，以及指标汇总页截图。系统不伪造个人姓名或手写签名；如赛事明确要求具名手写签字，应另附纸质签字扫描件。
