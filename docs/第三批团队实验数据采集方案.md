# 第三批团队实验数据采集方案

## 1. 建设目标

第三批不继续单纯增加公开论文，而是建立团队真实实验数据进入知识库的规范入口。首个试点方向为航空轮胎胎面橡胶热氧老化与滑动磨损，后续可按同一结构扩展航空刹车和复合材料实验。

## 2. 数据类型

- 样品信息与匿名批次；
- 热氧老化温度、时间、气氛和设备记录；
- 法向载荷、滑动速度、试验时间、摩擦力和温度；
- 质量损失、摩擦系数和磨损率等可复核计算；
- 光学、SEM 和宏观损伤图像；
- 裂纹、剥落、犁沟、黏着和磨屑等损伤标注；
- 案例机理假设、替代解释、证据关联和安全边界；
- 授权、隐私、质量控制和专家复核状态。

## 3. 模板位置

```text
D:\agents\knowledge_corpus\raw_docs\team_tire\
```

实验工作簿区分原始输入列和公式列，汇总页只统计 `qc_flag=pass` 的记录。图像工作簿通过 `sample_id`、`source_record_id`、`image_id` 和 `case_id` 形成可追溯链路。

## 4. 数据进入 RAG 的门槛

1. `authorization_status` 为 `team_owned`、`authorized` 或 `public`；
2. 不包含个人敏感信息或受限商业信息；
3. 实验和图像工作簿通过结构校验；
4. 原始附件、图片路径和 SHA-256 可核验；
5. 数据复核与专业复核均为 `approved`；
6. `approved_for_rag=true`；
7. 生成团队实验 Markdown 后再切片，不直接修改 ES 文档。

## 5. 校验命令

```powershell
cd D:\agents\backend
.\.venv\Scripts\Activate.ps1
python -m app.rag.team_dataset_validator
```

## 5.1 无真实数据时的阶段验收

当前阶段不要求录入团队真实数据。执行以下命令即可验证 Excel 解析、字段规范化、派生指标计算和 Markdown 生成链路：

```powershell
python -m app.rag.team_dataset_pipeline --dry-run-template
```

预览输出位于 `D:\agents\.tmp\team_tire_pipeline_preview.md`。模板中的 `DEMO-*` 行只用于管线测试，不写入 `parsed_docs`、`source_registry.json` 或 Elasticsearch。

## 5.2 真实数据就绪后的正式命令

完成数据替换、脱敏、授权确认和专业审核后，再执行：

```powershell
python -m app.rag.team_dataset_pipeline --ingest --index
```

正式入库必须同时满足：存在 `dataset_manifest.json`、授权状态有效、`review.review_status=approved`、`ingestion.approved_for_rag=true`，且所有正式记录均不以 `DEMO-` 开头。转换后先形成 Markdown 证据文档和来源登记，再进入统一切片与索引流程。

当前模板状态为 `ready / template`，尚无真实图片和真实 manifest，因此 `approved_for_rag=false`。这表示模板可开始填写，但不会误把示例数据写入正式知识库。

## 6. 后续步骤

1. 选择一组可公开或可授权的轮胎实验；
2. 复制模板工作簿并去掉文件名中的“模板”；
3. 删除或替换所有 `DEMO-` 示例行；
4. 填写真实实验条件和仪器附件路径；
5. 导入 10 至 30 张代表性损伤图片；
6. 完成数据负责人和专业导师复核；
7. 开发团队数据 Markdown 生成器和 ES 入库命令；
8. 增加基于真实案例的诊断题和图像判读任务。
