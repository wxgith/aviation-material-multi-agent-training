# 验收卡顿排查说明

## 适用范围

本文用于排查 `scripts/run_acceptance.ps1` 长时间停留在某一步、终端没有新输出或无法判断具体 case 的情况。排查时先保留现场，不要立即重跑完整 14 步，也不要停止正常运行的 FastAPI、Vite、MySQL 或 Elasticsearch。

## 第 3 步实际命令

完整验收的第 3 步实际执行：

```powershell
D:\agents\backend\.venv\Scripts\python.exe -u -m app.evaluation.runner --quiet --progress
```

推荐通过验收脚本的单步入口复现：

```powershell
cd D:\agents
.\scripts\run_acceptance.ps1 -OnlyStep 3
```

该命令只运行第 3 步，不访问后端 HTTP 接口，不连接 MySQL、Elasticsearch 或 LLM。runner 会临时强制使用 JSON、本地检索、无 BGE 和 mock 生成，完成后恢复进程内原设置。

## 进度含义

第 3 步会输出以下阶段：

| 阶段 | 数量 | 实际工作 |
| --- | ---: | --- |
| `core-case-validation` | 50 | 校验 50 条核心用例字段、分类和期望步骤，不逐条执行 Agent |
| `multidimensional-validation` | 10 | 校验增强用例及来源登记 |
| `retrieval` | 10 | 执行本地知识检索并核对 evidence ID |
| `agent-pipeline` | 3 | 分别执行轮胎、刹车片、复合材料的 6 Agent 样例 |
| `feedback-decision` | 10 | 校验反馈动作，含 8 条自动判定和 2 条人工复核标记 |

全量 50 条用例逐条通过 6 Agent 的执行属于完整验收第 4 步，不属于第 3 步。

每个单元开始时输出 `START`，结束时输出 `DONE`。若发生超时，错误信息会显示最后一条 `START`。最后一条 `START` 后没有相同 stage 和 case 的 `DONE` 时，才把该 case 视为优先嫌疑项。

## 日志位置

每个子命令会生成三个文件：

```text
outputs/acceptance/logs/<时间>-<步骤>.stdout.log
outputs/acceptance/logs/<时间>-<步骤>.stderr.log
outputs/acceptance/logs/<时间>-<步骤>.exitcode.log
```

查看最新第 3 步日志：

```powershell
$log = Get-ChildItem D:\agents\outputs\acceptance\logs\*-core-evaluation.stdout.log |
  Sort-Object LastWriteTime -Descending |
  Select-Object -First 1

Get-Content $log.FullName -Tail 30
```

查看最后一条尚未配对的进度时，先关注日志末尾的 `START` / `DONE`，再结合相同 case ID 搜索：

```powershell
Select-String -Path $log.FullName -Pattern 'START|DONE'
```

## 进程检查

检查是否仍有评测或验收子进程：

```powershell
Get-CimInstance Win32_Process |
  Where-Object { $_.CommandLine -match 'app\.evaluation\.|run_acceptance\.ps1' } |
  Select-Object ProcessId, ParentProcessId, Name, CommandLine
```

不要根据进程名直接结束全部 `python.exe` 或 `node.exe`，否则会同时关闭正常的 FastAPI 或 Vite。只处理命令行中明确包含对应评测模块、且已确认失去响应的 PID。

## 超时参数

第 3 步默认超时 120 秒，普通子命令默认超时 900 秒，心跳默认 15 秒。可以按需调整：

```powershell
.\scripts\run_acceptance.ps1 -OnlyStep 3 -Step3TimeoutSeconds 180 -HeartbeatSeconds 10
.\scripts\run_acceptance.ps1 -CommandTimeoutSeconds 1200 -HeartbeatSeconds 15
```

超时后脚本会结束对应子进程树并保留 stdout、stderr 和退出码日志。不要通过无限增大超时掩盖固定 case 的阻塞。
