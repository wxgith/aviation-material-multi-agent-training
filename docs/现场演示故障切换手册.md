# 现场演示故障切换手册

本手册用于比赛录屏、现场答辩或异机部署时快速判断工程模式是否正常，并在 MySQL、Elasticsearch 或 Docker 暂时不可用时切换到 JSON/mock 兜底模式。

## 1. 演示前推荐检查

打开 Docker Desktop，等待引擎启动完成，然后优先执行一键启动：

```powershell
cd D:\agents
.\scripts\start_project.ps1
```

脚本会检查容器、端口、后端异步任务接口和前端页面。如果看到 `Project is ready`，即可进入彩排。需要再次确认时执行：

```powershell
.\scripts\project_status.ps1
```

完整环境审计仍可执行：

```powershell
cd D:\agents
.\scripts\check_environment.ps1
```

正常状态应包含：

- `report-mysql`：PASS；
- `agents-es`：PASS；
- Backend API：PASS；
- MySQL connection：PASS；
- Elasticsearch connection：PASS；
- Frontend：PASS。

再执行：

```powershell
.\scripts\run_acceptance.ps1
```

出现 `Acceptance passed` 后再开始录屏或答辩。

## 2. 正式工程模式

`backend/.env` 推荐配置：

```env
DATA_BACKEND=sql
DATABASE_ENABLED=true
ES_ENABLED=true
LLM_ENABLED=false
BGE_ENABLED=false
RETRIEVAL_MODE=hybrid
```

健康检查：

```powershell
Invoke-RestMethod http://127.0.0.1:8000/api/health
```

重点字段：

```text
data_backend       = sql
database_connected = true
es_connected       = true
knowledge_source   = elasticsearch
llm_enabled        = false
```

## 3. Docker 或数据库异常时切换兜底模式

不要删除数据库、索引或知识文件。只修改 `backend/.env`：

```env
DATA_BACKEND=json
DATABASE_ENABLED=false
ES_ENABLED=false
LLM_ENABLED=false
BGE_ENABLED=false
RETRIEVAL_MODE=hybrid
```

保存后重启后端：

```powershell
cd D:\agents\backend
.\.venv\Scripts\Activate.ps1
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

前端不需要修改。再次查看健康检查，预期为：

```text
data_backend       = json
database_enabled   = false
es_enabled         = false
knowledge_source   = local-json
llm_enabled        = false
```

此时仍可演示：

1. 加载演示案例；
2. 提交诊断；
3. 运行 6 Agent；
4. 展示本地 JSON 检索依据；
5. 查看四类个性化资源；
6. 查看并导出学情报告；
7. 提交反馈并更新路径。

## 4. 不修改 .env 的兜底自检

需要证明兜底逻辑可运行、但不希望停止当前 Docker 服务时，执行：

```powershell
cd D:\agents
.\scripts\run_fallback_acceptance.ps1
```

该命令仅在测试进程中临时关闭外部组件，不会停止容器，不会修改 `.env`，也不会向 MySQL 写入记录。

结果文件：

```text
evaluation/fallback_acceptance_results.json
evaluation/fallback_acceptance_summary.md
submission_materials/07_接口测试与单元测试/JSON兜底模式验收报告.md
```

## 5. 恢复 SQL + ES 工程模式

确认 Docker 容器已经运行：

```powershell
docker start report-mysql
docker start agents-es
```

恢复 `backend/.env`：

```env
DATA_BACKEND=sql
DATABASE_ENABLED=true
ES_ENABLED=true
LLM_ENABLED=false
BGE_ENABLED=false
RETRIEVAL_MODE=hybrid
```

重启后端并检查：

```powershell
Invoke-RestMethod http://127.0.0.1:8000/api/health
curl.exe http://127.0.0.1:9201/aviation_material_knowledge/_count
```

当前冻结基线为 1,766 条 ES 文档。

## 6. 常见故障

| 现象 | 检查 | 处理 |
| --- | --- | --- |
| 前端打不开 | `http://127.0.0.1:5173` | 在 `frontend` 执行 `npm run dev` |
| 健康检查打不开 | 8000 端口和后端终端 | 重启 Uvicorn |
| MySQL 未连接 | `docker ps`、3306 端口 | 启动 `report-mysql`，或切换 JSON 模式 |
| ES 未连接 | `docker ps`、9201 端口 | 启动 `agents-es`，或切换本地检索 |
| ES 数量异常 | `/_count` | 正式演示先使用当前索引；不要现场重建 |
| 页面仍显示旧状态 | 浏览器缓存、后端重载 | 刷新页面并确认健康检查 |
| 导出按钮不可用 | 是否已完成 Agent 管线 | 先生成 session，再进入报告页 |
| 端口被占用 | `Get-NetTCPConnection` | 关闭旧服务后按固定端口重启 |

## 7. 现场原则

- 不在答辩现场执行 seed 或重建 ES 索引；
- 不临时接入真实 LLM；
- 不删除 MySQL、ES 或本地 JSON 数据；
- 工程模式异常超过两分钟时，直接切换 JSON/mock；
- 明确说明兜底模式是系统设计的一部分，不是临时伪造数据；
- 演示结束后再恢复工程模式并排查外部组件。
