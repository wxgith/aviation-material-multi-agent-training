# 答辩 PPT 文案

## 第 1 页：项目背景与痛点

页面正文要点：
- 航空工程材料损伤分析训练涉及材料基础、服役损伤、实验表征和维修判读。
- 学习者基础差异大，传统教材和普通问答系统难以形成持续训练闭环。
- 需要面向垂直领域的个性化知识生成与多智能体协同决策系统。

建议图示：
航空轮胎、航空刹车片、复合材料板三类对象；传统学习方式与智能训练闭环对比。

讲解词：
航空工程材料损伤分析不是单纯背概念，而是要把损伤现象、机理解释、表征证据和维护决策联系起来。普通聊天机器人缺少学情诊断、知识依据、专业审核和反馈迭代，因此本作品从一开始就设计为训练系统，而不是问答页面。

## 第 2 页：作品名称与应用场景

页面正文要点：
- 作品名称：《面向航空工程材料损伤分析的多智能体个性化知识生成与实操训练系统》。
- 目标用户：本科低年级学生、材料方向研究生、科研训练新手、机务维修新员工。
- 覆盖方向：航空轮胎胎面橡胶、航空刹车片、飞机复合材料板。

建议图示：
三类用户画像 + 三类训练方向入口。

讲解词：
系统面向航空工程学院和维修培训中的典型技能训练场景。不同学习者的基础和目标不同，因此系统先识别画像和薄弱点，再生成匹配难度的学习资源和训练路径。

## 第 3 页：航空工程材料损伤分析任务特点

页面正文要点：
- 航空轮胎：热氧老化、滑动磨损、胎面裂纹、剥落和损伤等级判读。
- 航空刹车片：高温摩擦、热衰退、氧化、裂纹和摩擦性能变化。
- 复合材料板：冲击损伤、分层、基体开裂、纤维断裂和无损检测判读。

建议图示：
材料方向与损伤任务矩阵。

讲解词：
这些任务的共同特点是专业术语多、证据链长、实操边界严格。系统需要同时考虑知识解释、实验表征、案例分析和决策建议，因此适合用多智能体拆分职责。

## 第 4 页：系统总体架构

页面正文要点：
- 前端层：React + Vite。
- 接口层：FastAPI REST API。
- 智能体层：六个职责明确的 Agent。
- 数据层：MySQL 持久化、Elasticsearch 知识库检索、JSON fallback。
- RAG 层：MinerU/Markdown 解析、知识切片、BM25/Vector/Hybrid 检索、BGE 可选扩展。
- 模型层：OpenAI-compatible LLM 受控调用、结构化输出校验、mock/template 自动回退。

建议图示：
五层系统架构图；右侧放 `/api/health` 状态截图。

讲解词：
当前工程增强版已经接入 MySQL 和 Elasticsearch。MySQL 用于保存诊断记录、Agent 会话、生成资源、报告、反馈和追问交互；Elasticsearch 用于检索航空工程材料知识库。系统支持 Markdown 切片、BGE embedding 扩展以及 BM25、Vector、Hybrid 检索模式，并实现基于当前画像和证据的启发式动态追问。真实 LLM 只有调用且校验成功时才标记为 LLM 生成，JSON fallback 和 mock/template 保证外部服务不可用时演示仍可继续。

## 第 5 页：多智能体协同机制

页面正文要点：
- 学情诊断 Agent：识别得分、等级和薄弱点。
- 材料路由 Agent：选择航空轮胎、刹车片或复合材料方向。
- 知识检索 Agent：从 ES 或 JSON fallback 检索依据。
- 资源生成 Agent：生成讲义、指南、测试题和案例。
- 审核纠偏 Agent：进行专业审核和风险提示。
- 路径决策 Agent：输出学习路径和下一步训练计划。

建议图示：
Agent 时间线或闭环流程图。

讲解词：
系统的核心不是把问题直接丢给一个大模型，而是让多个 Agent 依次完成分析、路由、检索、生成、校验和决策。每一步都有输入摘要、输出摘要、状态、置信度和证据 ID，便于展示和追溯。

## 第 6 页：领域知识库与学习者画像

页面正文要点：
- 内置三类学习者画像。
- 内置三类航空工程材料知识库切片。
- ES 索引 `aviation_material_knowledge` 已导入 1,766 条知识片段，覆盖官方维修资料、事故报告、开放获取论文、实验记录、开放数据集元数据和人工整理片段。
- FAA-H-8083-31B（2023）复材 NDI 与航空刹车检查维护摘录新增 81 条切片；研究论文用于机理解释，官方手册用于操作边界约束。
- 前端“知识证据库”可按领域筛选 39 条逻辑来源，展示授权边界、来源 ID、切片计数和 ES 入库状态。
- 已授权课题组轮胎资料形成 4 个专题、53 项已审核资产，包括热氧老化多模态证据、紫外跨时长形貌、实胎偏磨案例和 3×5 载荷-距离矩阵。
- 制动与复材当前没有团队实验数据，系统依据公开论文、NASA 报告和开放数据集整理 5 张实验卡；每张卡均给出试样、设备、工况、证据 ID、原文定位和适用限制，并已完成人工复核。
- `knowledge_corpus/index_manifest.json` 记录每条证据片段的来源和入库状态。
- MySQL seed 后 `learners` 表包含 3 条画像数据。

建议图示：
前端知识证据库与公开文献实验卡截图；ES 索引检查截图；DBeaver 中 `learners` 表截图；知识片段字段示例。

讲解词：
知识库不是只停留在前端静态 mock，而是具有从原始资料、MinerU 或 Markdown 解析、文本切片、索引清单到 Elasticsearch 检索的构建流程。对于当前没有团队实验数据的制动与复材方向，我们只提取公开论文和报告中可定位的实验事实，不把文献结果表述为本系统实测；5 张实验卡已经完成人工复核，10 条专项查询的 ES 来源命中率和证据可追溯率均为 100%。证据不足时由审核 Agent 降级输出。

## 第 7 页：个性化资源生成流程

页面正文要点：
- 输入：学习者画像、训练方向、诊断结果、ES 检索依据。
- 输出：定制化讲义、实操指南、分阶测试题、案例分析任务。
- 本科生采用现象引导型策略，研究生采用科研证据链型策略，机务人员采用检查决策型策略。
- 三类画像在讲义入口、记录模板、案例输出和测评层级上形成可验证差异。

建议图示：
资源页面截图；生成流程图。

讲解词：
系统会根据学习者水平和岗位目标改变资源结构，而不只是替换称呼或难度标签。本科低年级学生从可观察现象开始，研究生强化变量控制、定量交叉验证和外推边界，机务维修新员工则关注检查记录、复检和升级报告。四项画像差异自动指标均达到100%。

## 第 8 页：专家审核纠偏与幻觉防控

页面正文要点：
- 检查专业概念错误。
- 检查生成内容与知识库依据的一致性。
- 检查难度匹配和实操约束。
- 标注风险点、依据片段和纠偏建议。
- 区分实验观察、参数事实、机理推断和维护建议。
- 证据不足时输出越界声明、证据缺口和降级说明。
- 生成 Agent 提案与审核 Agent 证据核验形成交叉验证；引用、难度、工况或边界不满足时触发纠偏重生。
- 通过 50 条评测用例和专家复核表评估幻觉率。
- 同一批 6 个 RAG + Qwen 候选配对对照：审核前通过 3/6，审核纠偏后通过 6/6。

建议图示：
前端“结论—证据—边界交叉验证”面板；证据 ID 与风险点关联图。

讲解词：
在专业训练系统中，生成内容必须可审核、可纠偏、可追溯。生成 Agent 先提出资源草案，审核 Agent 再按结论、证据、工况和使用边界核验；不满足规则时系统会完成一次纠偏重生并再次复核。系统还对单图确定完整机理、补齐缺失温升、亮度直接等同老化程度、文件名推断参数和训练结果替代适航放行等请求进行拦截降级。5类高风险请求自动拦截率为100%；审核门控配对实验把同一批候选的机器通过数从 3/6 提升到 6/6。这里明确区分工程机器测评、项目组核心用例复核和待采集的外部专家盲审，不把内部指标冒充外部结论。

- 50 条核心用例已逐条进入诊断和 6 Agent 管线，完整执行 50/50 通过，Agent 完整率 100%。
- 机器辅助核心知识点覆盖代理值为 97.27%，8 条审核用例完成首审驳回、纠偏重生和二审通过。专家语义复核进一步确认专业正确率 100%、核心知识点覆盖率 100%、幻觉率 0%、难度适配准确率 100%；项目负责人于 2026-08-10 完成电子确认。

- MySQL 已写入诊断、会话、步骤、资源、报告和反馈。
- ES 索引包含 1,766 条知识片段，并可按 `source_id`、证据 ID 和章节或页码追溯原始依据。
