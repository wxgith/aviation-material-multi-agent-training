# 三领域资料补强行动清单

本清单由 `python -m app.evaluation.knowledge_coverage_runner` 的库存覆盖分析生成后人工整理。它指导后续找资料和入库，但不把切片数量等同于专业准确率。

## 1. 当前结论

| 领域 | 当前优势 | 主要缺口 | 优先级 |
| --- | --- | --- | --- |
| 航空轮胎 | 团队授权实验、多工况形貌、老化与磨损证据链完整 | 继续做专家抽样、来源许可终审 | 保持 |
| 航空刹车 | FAA/NASA/开放论文覆盖结构、维护、高温摩擦和失效机理 | 缺少团队或授权实验的原始工况表、曲线、形貌配对 | 高 |
| 复合材料 | FAA/NASA、开放数据和 NDI 文献覆盖较广 | 缺少自有/授权的冲击工况、C-scan/CT 配对和专家判读记录 | 高 |

量化报告见 `evaluation/knowledge_coverage_summary.md`。当前库存代理分不是模型准确率，也不是安全放行能力。

## 2. 航空刹车优先寻找的资料

优先级 A：可授权实验或教学实验数据。

1. 试样与材料信息：C/C、粉末冶金或其他刹车材料，记录牌号、尺寸、密度和制样方式。
2. 工况表：制动能量、法向载荷/压力、初速度、转速、环境温度、重复次数和冷却方式。
3. 同步曲线：摩擦系数、界面/背板温度、时间或制动次数。
4. 试验前后质量、厚度或磨损率记录，并保留单位和仪器精度。
5. 同一工况对应的光学、SEM 或三维形貌图，标明倍率、比例尺和样品编号。
6. 热衰退与恢复循环，区分“观察事实”“机理解释”和“维护含义”。
7. 由材料或机务教师填写的判读记录，尤其是氧化、沟槽、剥落与热裂纹边界。

优先级 B：公开且可追溯资料。

- NASA/NTRS、FAA 官方维护资料；
- 带明确 CC BY 许可的实验论文与开放数据；
- 学校合法订阅的标准仅登记元数据和条款定位，不复制全文进入提交包；
- 制造商维护手册只有在获得授权时使用，且不能替代当前适航批准数据。

## 3. 复合材料优先寻找的资料

优先级 A：冲击工况与无损检测成对数据。

1. 层合板铺层、材料体系、厚度、试样尺寸和边界支撑。
2. 冲击能量、冲击头质量/直径、速度、位置和重复编号。
3. 冲击后正反面照片，保留比例尺和凹坑深度。
4. 同一试样的超声 C-scan、X-ray CT、热成像或敲击检测结果。
5. 分层面积、深度位置、基体开裂/纤维断裂标签及标注人。
6. 有条件时补截面或破坏性验证，用于核对无损检测结果。
7. 专家判读表：可见损伤、内部损伤风险、建议复检方法、结论边界。

优先级 B：开放数据。

- 优先使用 DOI、作者、许可和数据字典齐全的数据集；
- 当前已登记 `composite_zenodo_4405277`，但原数据尚未随包提供；下载前先复核数据许可和体积；
- ASTM D7136 等受版权保护标准只登记版本、合法访问方式和试验字段，不存未授权全文。

## 4. 文件保存位置

每份资料按以下路径流转：

```text
knowledge_corpus/
  raw_docs/
    brake/                 # 原始 PDF、公开数据说明、授权实验归档
    composite/
  parsed_docs/             # MinerU 或人工清洗后的 Markdown
  chunks/                  # RAG pipeline 生成的 JSON 切片
  source_registry.json     # 来源、许可、校验值、适用章节和状态
  index_manifest.json      # 最终切片和 ES 入库状态
```

团队原始图片和曲线先放在外部授权介质或 `raw_docs/.../pending_review/`，完成以下四项后才能进入正式语料：

1. 授权确认；
2. 学号、姓名、设备编号等敏感字段脱敏；
3. 专业人员核对工况与单位；
4. 建立样品 ID、工况、图像和结论之间的映射。

## 5. 最小登记字段

在 `source_registry.json` 中至少登记：

- `source_id`、`domain`、`title`；
- 作者/机构、年份、文档类型、DOI 或 URL；
- `license_or_authorization`；
- `local_file` 和 SHA-256；
- `applicable_sections`；
- `acquisition_status`；
- 页码、图号、表号或实验记录定位；
- 使用边界与待确认问题。

公开网页本身不是充分证据。入库内容必须能回到具体文献页码、图表、数据文件或实验编号。

## 6. 入库与验证

```powershell
cd D:\agents\backend
.\.venv\Scripts\Activate.ps1

# PDF/JATS 或 MinerU Markdown 解析后
python -m app.rag.pipeline

# 重新生成覆盖差距报告
python -m app.evaluation.knowledge_coverage_runner

# 全量回归
pytest
```

资料增加后应检查：ES 文档数变化是否符合预期、来源 ID 是否可检索、生成内容是否引用有效 evidence ID，以及专家复核表是否覆盖新加入的实验事实。
