# 数据脱敏与命名规范

## 1. 不得进入项目的内容

- 姓名、学号、身份证号、手机号、个人邮箱和签名；
- 未经授权的企业名称、供应商配方、型号报价和内部工艺参数；
- 可直接识别实验人员或合作单位的照片、水印和文件属性；
- 尚未公开且不允许用于比赛展示的数据。

## 2. 代码规则

- 数据集：`TIRE-EXP-YYYY-NNN`
- 样品：`TIR-{批次代码}-{老化条件}-{重复号}`
- 老化工况：`AGE-{温度C}-{时间h}`
- 磨损记录：`WEAR-{日期}-{三位序号}`
- 图像：`IMG-{样品ID}-{类型}-{视场序号}`
- 案例：`CASE-TIRE-{四位序号}`
- 人员：只使用 `OP-A`、`REVIEWER-B` 等角色代码。

文件名仅使用 ASCII 字母、数字、连字符和下划线，扩展名保持小写。例如：

```text
IMG-TIR-B01-AGE100C72H-R01-SEM-F01.tif
IMG-TIR-B01-AGE100C72H-R01-OPT-F02.jpg
instrument-WEAR-20260804-001.csv
```

## 3. 图像要求

- 原始图像不裁剪、不涂抹，另存标注版；
- 记录倍率、标尺、设备代码、样品位置和采集日期；
- 清除真实姓名、软件登录名和设备网络路径；
- `relative_path` 必须相对于 `team_tire/`；
- 计算 SHA-256，用于确认图片未被替换。

## 4. 数据修订

- 原始测量只追加，不覆盖；
- 修订值写入处理结果或备注字段；
- 异常、排除和缺失必须填写 `qc_flag` 与原因；
- 单位必须写在列名中，单元格只填数值；
- 小数点使用 `.`，日期使用 `yyyy-mm-dd`。

## 5. 授权状态

`authorization_status` 只允许：

- `pending`：待确认，不允许入库或比赛展示；
- `team_owned`：团队自有；
- `authorized`：已取得明确授权；
- `public`：公开资料；
- `restricted`：受限，只可保存在本地，不得提交。
