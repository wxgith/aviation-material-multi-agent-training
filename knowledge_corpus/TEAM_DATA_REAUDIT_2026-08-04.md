## 3. 当前系统承载缺口

1. 前端能显示检索模式、知识来源、证据标题和 `evidence_id`，但不能直接打开对应实验图像或曲线。
2. RAG 清单没有统一的 `asset_ids`、缩略图路径、实验工况和样品主键字段，文字切片与多模态资产未形成一对一绑定。
3. 50 条测评用例已覆盖五类流程，但没有以 RXQ/LYQ 团队实验数据为明确预期证据的专项用例。
4. 生成资源主要是文字模板，尚未形成“给出实验图像/曲线 -> 学员判读 -> Agent 按证据评分”的实操闭环。
5. 缺少实验数据质量分级：已确认、待专家复核、仅作线索三种状态应在检索和生成时区别处理。

## 4. 下一阶段建议

下一阶段建议命名为：**第八阶段：团队实验多模态案例库与证据闭环**。

### 第一批：数据模型和证据服务

1. 定义统一实验资产结构：`experiment_id`、`sample_id`、`condition`、`modality`、`asset_id`、`source_path`、`review_status`、`evidence_id`。
2. 新增代表性图像缩略图和曲线图生成流程，不复制全部原始大文件。
3. 后端提供证据详情接口，使检索结果可返回图片、曲线、工况、来源和审核状态。
4. 前端增加“实验依据”区域，展示证据卡片或证据抽屉，不改动现有主流程。

### 第二批：两个正式专题数据集

1. 优先整理“实胎偏磨与严重度判读”数据集。
2. 优先整理“热氧老化多表征证据链”数据集。
3. 每个专题先选 10 至 20 个高置信样品，不追求一次导入全部数据。
4. 为每个样品建立人工复核字段和可追溯源路径。

### 第三批：多模态训练与测评

1. 新增图像判读、曲线解释、表征方法选择和耦合损伤归因四类训练任务。
2. 增加至少 20 条团队实验专项测评用例，明确预期 `evidence_id` 或 `asset_id`。
3. 增加证据命中率、图像判读准确率、工况归因准确率和专家一致性指标。
4. 录制演示时展示“ES 检索文字依据 + 团队实验图像/曲线依据 + MySQL 学习记录”。

### 第四批：耦合损伤高级专题

1. 整理老化后摩擦与摩擦后老化的顺序效应。
2. 建立载荷、温度、距离、老化时间的多因素案例矩阵。
3. 在专家复核后形成损伤边界训练任务；避免把实验相关性表述成适航判据或工程放行标准。

## 6. 决策结论

现阶段最缺的不是更多原始文件，也不是立即接入真实 LLM，而是把已有真实实验资料转化为可在系统中看到、可追溯、可训练、可评价的证据。下一阶段应以两个小而完整的正式专题为中心：实胎偏磨判读和热氧老化多表征。待这两个专题跑通后，再扩展紫外后摩擦和耦合顺序效应。
